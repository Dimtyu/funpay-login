Про «страницу на GitHub»

Тут важный момент: 09nikitoz95-svg.github.io — это бесплатный хостинг GitHub Pages, а не «вход через GitHub». Это обычная HTML-страница, которая отправляет форму на их сервер. Никакого GitHub-аккаунта там нет.

Сделать такую же страницу на GitHub Pages можно, но есть три проблемы:

  1. Ваш сервер не пустит запрос — нужен CORS и отдельный JSON-эндпоинт для активации.
  2. Код активации будет виден в исходниках страницы на GitHub — любой склонирует.
  3. Смысла мало: страница всё равно откроет ваш сайт для создания кабинета. Лишний шаг, который ломается.

Почему у образца так сделано

Там форма ведёт на riskradarai.ru/api/github/register — то есть их страница на GitHub Pages просто отправляет данные к ним на сервер. Название «github» в пути — просто потому что страница лежит на GitHub. Это не интеграция с GitHub.

Что реально стоит решить

Есть три разных сценария, и они несовместимы. Скажите, какой нужен:

Вариант А — как сейчас (продажа баланса). Код одноразовый, даёт деньги. Человек активирует на /promo, создаёт аккаунт, потом входит почтой и паролем. Это то, что уже работает и то, что я настроил под FunPay.

Вариант Б — пропуск на вход. Код не даёт денег, а создаёт/открывает кабинет. Многоразовый, но привязан к первому аккаунту. Подходит, если вы продаёте не баланс, а доступ.

Вариант В — гибрид: код даёт баланс + создаёт аккаунт, а повторный вход — по логину и паролю (то, что у вас есть). Промокод при этом одноразовый.

Судя по тому, что вы продаёте токены на FunPay, вам нужен вариант В — он уже готов. А идея с «входом много раз через промо» конфликтует с продажами: один код = один покупатель.

Что я добавил на сервере

  • POST /api/promo/check — отдаёт только «годен / не годен» и сумму. Никаких данных аккаунта, без cookies. Лимит 30 попыток за 10 минут с одного IP — от перебора.
  • /promo?code=… — принимает код в ссылке и пропускает сразу к регистрации.
  • Общая проверка _promo_public_error() — одна логика для сайта и API, чтобы они не разошлись.

Как залить на GitHub

  1. Создайте репозиторий, например funpay-login
  2. Загрузите туда (изменять имя не нужно — GitHub Pages откроет его по умолчанию)
  3. Settings → Pages → Source: Deploy from a branch → ветка main, папка / (root) → Save
  4. Через минуту страница будет на https://ВАШ_НИК.github.io/funpay-login/

Три честных предупреждения

Адрес сайта в файле зашит. В строке var SITE = "https://neuraltoken.ru"; — если переедете на другой домен, поменяйте там же.

Файл публичный. Любой может открыть исходник страницы и увидеть адрес API. Это не проблема: эндпоинт и так публичный, а перебор кодов ограничен лимитом. Чего в файле нет — так это секретов.

Это не «вход через GitHub». Страница просто лежит на GitHub Pages. Если в будущем захотите настоящий вход через GitHub OAuth — это отдельная история, и она вам, судя по продажам, не нужна.
